# 원본에서 바뀐 것

**원본:** 노슈니(오수인)님의 `threads-writing` (스폰지클럽 3기 스킬러스 유닛 공유)
**갈라진 날:** 2026-09-03

---

## 왜 바꿨나 — 한 문장

원본을 받아서 써보니 **만든 사람의 재료가 파일 안에 박혀 있었다.**
그래서 **「만드는 방식」과 「쓰는 사람의 재료」를 분리**했다.

---

## 바꾼 것 5가지

### 1. 재료를 스킬 밖으로 뺐다 ⭐ 가장 큰 변화

| | 원본 | 이 스킬 |
|---|---|---|
| 글쓴이 정보 | 파일 안에 있음 | **폴더 밖 `sns-writing-private/`** |
| 소재 | 파일 안에 예시로 있음 | **폴더 밖 `material-stash.md`** |
| 어투 | 만든 사람 문체가 배어 있음 | **폴더 밖 `my-voice.md`** — 쓸수록 쌓임 |

**왜:** 등록하면 공개 저장소에 올라간다. 개인 정보를 애초에 안 넣으면 지울 일도 없다.
그리고 **남이 받아도 자기 재료로 바로 돈다.**

`SKILL.md` 맨 앞에 재료 폴더를 찾는 순서를 넣었다. **없으면 그냥 물어보며 진행한다 — 안 깨진다.**

### 2. 채널을 고르는 0단계를 새로 넣었다

원본은 스레드 전용이었다. 스레드 규칙(7~12칸·볼드 금지)이 본체에 섞여 있었다.

**본체에서 떼어내 채널 파일로 분리했다.**

```
references/channel-threads.md      ← 본체에서 떼어낸 스레드 규칙
references/channel-instagram.md    ← 원본 cardnews.md 를 채널 파일로 승격
```

**왜:** 채널을 추가할 때 `channel-○○.md` 한 장만 더 쓰면 된다.
훅·소재·재료는 그대로 재사용된다.

### 3. 채널을 가리지 않는 원칙을 본체로 올렸다

원본에서 스레드 얘기와 섞여 있던 것 중 **어느 채널에서든 통하는 5가지**를 본체로 뽑았다.

1. 첫 자리가 전부다 · 2. 자극은 세게, 상처는 없게 · 3. 글의 두 유형 ·
4. 문장 기술 · 5. 마무리와 CTA

*"1번 칸"* 이라는 스레드 전용 표현을 **"첫 자리(스레드 1번 칸 · 인스타 표지)"** 로 바꿨다.

### 4. 훅 예시에서 실존 인물·브랜드를 뺐다

원본 훅 예시 8개 중 **3개가 실존 인물·브랜드**를 그대로 쓰고 있었다.

| 유형 | 원본 | 바꾼 것 |
|---|---|---|
| 손해를 먼저 말하기 | 특정 브랜드·유통 채널 이름 | 이름 없이 구조만 |
| 통념 뒤집기 | 특정 가수·곡 이름 | 이름 없이 구조만 |
| 반박 불가능한 관찰 | 특정 가수·곡 이름 | 이름 없이 구조만 |

**왜:** ① 예시가 「형태」를 보여주면 되지 특정 인물이 필요하지 않다.
② 실존 인물을 예시로 박아두면 그 각도로만 생각하게 된다.

### 5. 소재 파일에 「재료 폴더가 먼저」라는 순서를 박았다

원본 `topic-mining.md` 는 카테고리만 있어서, 매번 사용자에게 질문해 캐내는 구조였다.

**앞에 순서를 넣었다.**
1. 재료 폴더의 `material-stash.md` 를 **먼저** 읽는다
2. 거기서 카테고리에 맞춰 후보를 뽑는다
3. 비어 있으면 *"대화에서 캐 올까요?"* 를 먼저 제안한다 (`material-harvest` 로 넘김)
4. 마다하거나 `material-harvest` 가 없을 때만 질문으로 캐낸다

## 2026-10-14 · 세 스킬 문서끼리 어긋난 곳 맞춤

원본과는 상관없는, 카라 OS 안에서의 손질이다. 한 번에 묶어 적는다.

**sns-writing**

- `EXAMPLE.md` 에 **「쓰기 전에 사실을 맞춥니다」** 장면을 넣었다. 2단계(사실 확인)가 예제에 없었다.
  글에 나오는 숫자(3초 · 30초 · 버튼 일곱 개 · 다섯 개 · 두 개)는 이제 **전부 클로드가 묻고 사용자가 답한 것**이다.
- 같은 장면에서 **「언제 올리실 건가요?」** 를 묻고, 올리는 날(9월 9일) 기준으로 1번 칸의 「어제」를 정한다.
- `templates/who-i-am.md` 의 「캐지 말 폴더」 칸 설명을 **「여기 적은 폴더만 잠긴다. 골라도 열지 않는다」** 로 고쳤다.

**source-to-lead**

- 링크 비율을 **「보내는 글 하나에 믿게 만드는 글 둘 이상」** 으로 맞췄다 (`README.md` · `SKILL.md` 원칙 2).
- 믿게 만드는 글을 **「본문에는 링크 없음. 프로필 안내 한 줄은 된다」** 로 맞췄다 (`README.md` · `SKILL.md` · `references/placement.md` · `EXAMPLE.md`).
- `EXAMPLE.md` 의 4편(「몇 명이 받아 갔다」)을 **믿게 만드는 글**로 바꿨다. 결과만 알리고 링크는 뺐다 — 믿게 만드는 글 셋에 보내는 글 하나.
  2편 전용이던 링크는 **「인스타 프로필용 링크 하나」** 로 이름을 바꿨다.
- 6단계 순서에 **「결과만 알리는 글은 보내는 글 뒤에 와도 된다」** 를 붙였다. 예제 4편(9/16)이 보내는 글인 3편(9/13) 뒤에 오기 때문이다 (`SKILL.md` · `EXAMPLE.md`).
- `references/utm.md` 끝을 **「세는 표를 만드는 것까지 이 스킬이 한다. 숫자는 사용자가 각 서비스 화면에서 가져온다」** 로 고쳤다. `SKILL.md` 7단계와 맞춘 것이다.
- `templates/who-i-am.md` 는 sns-writing 과 같게 고쳤다.

**material-harvest**

- 🔒 잠긴 폴더는 **사용자가 직접 골라도 이 스킬에서는 열지 않는다.** 열려면 `who-i-am.md` 에서 잠금을 먼저 풀라고 안내한다 (`SKILL.md` · `README.md` · `EXAMPLE.md` · 견본).
- `README.md` 를 **「who-i-am.md 에 적어 둔 폴더만 잠깁니다」** 로 고치고, `SKILL.md` 도 같게 맞췄다.

**그 밖에 함께 맞춘 것**

- source-to-lead `README.md` · 맨 위 `README.md` 의 예시 표에서 링크가 붙은 글을 「결과 알림」에서 「신청 안내」로 바꿨다. 결과만 알리는 글에는 링크를 붙이지 않기 때문이다. 인스타 칸은 「프로필 안내 한 줄」로, 맨 위 README 의 비율은 「보내는 글 한 편에 믿게 만드는 글 두 편 이상」으로 맞췄다. (설치 안내는 건드리지 않았다)
- source-to-lead `SKILL.md` 0단계 그림의 「링크 없음」을 「본문 링크 없음」으로 바꿨다.
- source-to-lead `EXAMPLE.md` 1편 날짜를 9/10 에서 9/9 로 바꿨다. sns-writing 예제에서 같은 글을 9월 9일에 올리고, 그래야 1번 칸의 「어제」(9월 8일)가 맞는다.
- material-harvest 부르는 말에서 *"쓸 만한 얘기 뭐 있었지"* 를 뺐다. 캐라는 말이 아니라 글감을 찾는 말이라 sns-writing 이 먼저 받는다.
- 위 「5. 소재 파일에…」의 순서를 지금 `topic-mining.md` 와 같게 고쳤다.

**예제 맨 끝 줄**

- sns-writing · source-to-lead 의 `EXAMPLE.md` 맨 끝 줄에 **이번에 손으로 고친 곳**을 밝혔다. material-harvest 예제와 같은 방식이다.
