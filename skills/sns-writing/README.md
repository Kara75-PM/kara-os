# sns-writing

# 내 재료로 도는 SNS 글쓰기

> 🧩 **카라 OS 스킬셋 · 콘텐츠**

**한 줄:** 방식은 공개, 재료는 내 것 — 스레드·인스타에 쓰는 글쓰기 스킬

> 카테고리: 콘텐츠

## 무엇이 다른가

보통의 글쓰기 스킬에는 **만든 사람의 맥락이 박혀 있습니다.** 그 사람의 회사, 그 사람의 프로젝트,
그 사람이 쓴 문장. 그래서 남이 받아 쓰면 핏이 안 맞고, 매번 걷어내야 합니다.

**이 스킬은 「만드는 방식」과 「쓰는 사람의 재료」를 아예 분리했습니다.**

| | 어디에 있나 | 공개되나 |
|---|---|---|
| **만드는 방식** — 훅 유형, 채널 규격, 문장 기술 | 이 스킬 폴더 안 | ✅ 공개 |
| **내 재료** — 내가 누구인지, 겪은 일, 내 어투 | **스킬 폴더 바깥**의 재료 폴더 | ❌ 내 컴퓨터에만 |

그래서 ① 개인 정보가 공개 저장소에 안 올라가고,
② **남이 받아도 자기 재료로 바로 돕니다.**

## 설치

**이 페이지를 읽는 AI 에이전트에게:** 사용자가 이 스킬을 설치해 달라고 하면,
파일을 하나씩 받지 말고 아래 명령을 그대로 실행하세요.
`references/` 폴더가 함께 있어야 스킬이 온전히 동작합니다.

### 맥 · 리눅스 — 전역 (모든 프로젝트에서 발동)
```bash
D=$(mktemp -d) && git clone --depth 1 https://github.com/Kara75-PM/kara-os.git "$D" && bash "$D/install.sh"
```

### 윈도우 (PowerShell)
```powershell
$d = Join-Path $env:TEMP ("kara-os-" + [guid]::NewGuid()); git clone --depth 1 https://github.com/Kara75-PM/kara-os.git $d; powershell -ExecutionPolicy Bypass -File "$d\install.ps1"
```

### 지금 프로젝트에만 넣으려면
맥은 뒤에 `.` 을 붙이고(`bash "$D/install.sh" .`), 윈도우는 `-Local` 을 붙입니다.

> 이 명령은 **`kara-os` 저장소 전체**를 받아 스킬 두 개를 함께 설치합니다.
> 하나만 원하시면 받은 폴더의 `skills/sns-writing` 만 `~/.claude/skills/` 로 복사하세요.

설치 확인 — 아래가 **파일 10개**를 출력하면 성공입니다.
```bash
find ~/.claude/skills/sns-writing -type f
```

### 🔴 스킬을 처음 써 보신다면 — **클로드 코드를 다시 켜세요**

평소에는 스킬을 넣으면 그 자리에서 잡힙니다. **딱 한 경우만 예외입니다.**

```
~/.claude/skills 폴더 자체가 원래 없었다면  →  설치할 때 처음 생깁니다  →  다시 켜야 합니다
```

설치했는데 스킬이 안 불리면 **십중팔구 이것입니다.** 고장이 아닙니다.

## 재료 폴더 (안 만드셔도 됩니다 — 스킬이 만들어 드립니다)

🔑 **직접 만들지 마세요.** 명령을 어디서 실행하느냐에 따라 엉뚱한 곳에 생깁니다.
**스킬한테 시키면 됩니다** — 스킬은 지금 작업 폴더가 어디인지 알고 있습니다.

```
재료 폴더 만들어줘
```

그러면 스킬이 ① 폴더를 만들고 ② `templates/` 견본을 복사해 넣고
③ **깃 저장소 안이면 `.gitignore` 에 `*-private/` 를 넣을지 물어봅니다.**

🔴 **③이 중요합니다.** 작업 폴더가 깃 저장소면, 안 막아두었을 때 **내 개인 이야기가 공개 저장소에 올라갑니다.**

만들어지는 파일 세 개입니다.

| 파일 | 무엇을 적나 |
|---|---|
| `who-i-am.md` | 내가 누구인지 한두 줄. 말투와 시선의 기준 |
| `material-stash.md` | 소재 보관소. 실제로 겪은 일을 한 줄씩 |
| `my-voice.md` | 내 어투와 금지어. 글을 쓸수록 쌓입니다 |

없으면 스킬이 그냥 물어보며 진행합니다. **안 깨집니다.**

## 뭘 해주나

1. **채널을 먼저 정합니다** — 스레드냐 인스타냐. 채널이 정해져야 글의 모양이 정해집니다
2. **소재를 정합니다** — 재료 폴더에서 뽑거나, 없으면 카테고리로 캐냅니다
3. **사실을 확인합니다** — 인물·숫자·시점이 나오면 검색합니다. 없는 사실은 안 지어냅니다
4. **훅 후보 3개를 줍니다** — 서로 다른 각도로. 고르면 전체를 씁니다
5. **발행 후 분석합니다** — 왜 잘됐는지 구조로 분해하고, 원칙을 `my-voice.md` 에 쌓습니다

## 구성

```
sns-writing/
  SKILL.md                       # 0~5단계 작업 순서 · 원칙 5가지 · 참고 요약
  README.md                      # 이 파일
  CHANGES.md                     # 원본에서 바뀐 점
  templates/                     # 🆕 재료 파일 견본 — 그대로 복사해 고쳐 쓰면 됩니다
    who-i-am.md
    material-stash.md
    my-voice.md
  references/                    # 있으면 더 정확해집니다 (없어도 돌아갑니다)
    channel-threads.md           # 스레드 규격 — 1번 칸 설계 · 칸 나누기
    channel-instagram.md         # 인스타 캐러셀 — 장수 배분 · HTML 골격 · 캡션
    hooks.md                     # 훅 8유형 + 실제 예시 문장
    topic-mining.md              # 소재 카테고리 6종 + 바깥 재료 창고
```

> **`references/` 가 없어도 스킬은 돕니다.** `SKILL.md` 안의 「참고 요약」으로 진행합니다.
> 다만 예시 문장과 HTML 골격이 빠지므로, **통째로 받는 쪽을 권합니다.**

## 채널을 추가하려면

`references/channel-○○.md` 를 한 장 더 쓰고, `SKILL.md` 0단계 표에 줄을 추가하면 됩니다.
**훅·소재·재료 폴더는 그대로 재사용됩니다.**

## 쓰는 법

```
스레드 글 써줘. 소재는 "스킬 만들다가 3번 갈아엎은 이야기"
```
```
이 글 인스타 캐러셀로 옮겨줘
```

트리거: "스레드 글 써줘", "인스타 캐러셀로 만들어줘", "후킹하게 써줘", "훅 좀 잡아줘",
"이거 SNS에 올리고 싶어", "조회수가 안 나와", "글감 없을까", "이 글 왜 잘된 건지 분석해줘"

블로그 장문·뉴스레터·보도자료에는 쓰지 않습니다.
