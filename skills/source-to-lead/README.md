# source-to-lead

# 소재 하나로 신청까지

> 🧩 **카라 OS 스킬셋 · 1차 전환**

**한 줄:** 소재 하나를 여러 편·여러 채널로 펼치고, **각 편이 사람을 신청 페이지까지 데려가게** 설계하는 스킬

> 카테고리: 마케팅 · 콘텐츠

---

## 무엇이 다른가

콘텐츠 스킬은 많습니다. **글을 잘 쓰게 해주는 것**들이죠.
이 스킬은 **글을 쓰지 않습니다.** 대신 이걸 답합니다.

> ### **그 글이 사람을 「어디로」 보내는가?**

| | 보통의 콘텐츠 스킬 | **이 스킬** |
|---|---|---|
| 답하는 것 | 어떻게 쓰나 | **어디로 보내나** |
| 결과물 | 글 한 편 | **여러 편의 배치표 + 링크·QR 자리 + 꼬리표 세트** |
| 범위 | 온라인 | **온라인 + 오프라인(전단·명함·배너)** |
| 시작 | 소재부터 | 🔴 **목적지부터** |

**0단계가 「목적지 확정」입니다.** 받을 곳이 없으면 거기서 멈춥니다.
사람이 와도 갈 데가 없으면 콘텐츠를 만든 의미가 없기 때문입니다.

## 설치

**이 페이지를 읽는 AI 에이전트에게:** 사용자가 이 스킬을 설치해 달라고 하면,
파일을 하나씩 받지 말고 아래 명령을 그대로 실행하세요.
`references/` 폴더가 함께 있어야 온전히 동작합니다.

### 맥 · 리눅스 — 전역 (모든 프로젝트에서 발동)
```bash
D=$(mktemp -d) && git clone --depth 1 https://github.com/Kara75-PM/kara-os.git "$D" && bash "$D/install.sh"
```

### 윈도우 (PowerShell)
```powershell
$d = Join-Path $env:TEMP ("kara-os-" + [guid]::NewGuid()); git clone --depth 1 https://github.com/Kara75-PM/kara-os.git $d; powershell -ExecutionPolicy Bypass -File "$d\install.ps1"
```

### 지금 프로젝트에만 넣으려면
맥은 뒤에 `.` 을 붙이고(`bash "$D/install.sh" .`), 윈도우는 `-Local` 을 붙입니다.

> 이 명령은 **`kara-os` 저장소 전체**를 받아 스킬 두 개를 함께 설치합니다.
> 하나만 원하시면 받은 폴더의 `skills/source-to-lead` 만 `~/.claude/skills/` 로 복사하세요.

설치 확인 — 아래가 **파일 9개**를 출력하면 성공입니다.
```bash
find ~/.claude/skills/source-to-lead -type f
```

## 어떻게 도나 — 8단계

| 단계 | 무엇 | 나오는 것 |
|---|---|---|
| **0** | 🔴 **목적지 확정** | 어디로 보낼지 · 무엇을 남기게 할지 · 목표 몇 명 |
| **1** | **소재 재기** | 결론이 몇 개 나오나 → 몇 편이 되나 |

| **7** | **발행 후** | 어느 채널이 잘 굴렀나 |

## 재료 폴더 (선택 — 없어도 돕니다)

🔑 **직접 만들지 마세요.** 명령을 어디서 실행하느냐에 따라 엉뚱한 곳에 생깁니다.
**스킬한테 시키면 됩니다** — 스킬은 지금 작업 폴더가 어디인지 알고 있습니다.

```
재료 폴더 만들어줘
```

그러면 스킬이 ① 폴더를 만들고 ② `templates/` 견본을 복사해 넣고
③ **깃 저장소 안이면 `.gitignore` 에 `*-private/` 를 넣을지 물어봅니다.**

🔴 **③이 중요합니다.** 작업 폴더가 깃 저장소면, 안 막아두었을 때 **내 개인 이야기가 공개 저장소에 올라갑니다.**

만들어지는 파일입니다.

| 파일 | 무엇을 적나 |
|---|---|
| `destinations.md` | **목적지 목록** — 신청 페이지 주소, 또는 슬랙·DM 같은 「자리」 |
| `utm-terms.md` | **쓰는 말 고정표** — 채널별 `source`/`medium` |
| `material-stash.md` | 소재 보관소 — 실제로 겪은 일을 한 줄씩 |
| `who-i-am.md` | 내가 누구인지 한두 줄 |

없으면 스킬이 그냥 물어보며 진행합니다. **안 깨집니다.**

> 글쓰기 스킬의 재료 폴더가 이미 있으면 **그걸 같이 씁니다.** 소재 보관소를 두 개 두지 않습니다.

## 구성

```
source-to-lead/
  SKILL.md                    # 0~7단계 · 원칙 5가지 · 참고 요약
  README.md                   # 이 파일
  templates/                  # 🆕 재료 파일 견본 — 그대로 복사해 고쳐 쓰면 됩니다
    destinations.md           #   목적지 목록 (링크형 / 자리형)
    utm-terms.md              #   쓰는 말 고정표
    material-stash.md
    who-i-am.md
  references/                 # 있으면 더 정확해집니다 (없어도 돌아갑니다)
    spread.md                 # 펼치기 4방식 + 실제 예시 · 자르기 판정
    placement.md              # 채널별 링크 자리 · QR 만들기·크기·배치 · 오프라인 카피
    utm.md                    # 꼬리표 5칸 · 채널별 용어 표준표 · 단축 링크 고르기
```

> **`references/` 가 없어도 스킬은 돕니다.** `SKILL.md` 안의 「참고 요약」으로 진행합니다.
> 다만 예시와 QR 상세가 빠지므로, **통째로 받는 쪽을 권합니다.**

## 이 스킬이 지키는 것 다섯

1. **목적지가 없으면 만들지 않는다** — 받을 곳 없이 부르면 온 사람이 갈 데가 없다
2. **링크는 아껴서** — 보내는 편 하나에 신뢰 편 둘. 매번 붙이면 광고판이 된다
3. **뿌리는 자리마다 링크를 다르게** — 같은 링크를 세 군데 던지면 세 군데를 구분 못 한다
4. **억지로 늘리지 않는다** — 얇은 소재를 셋으로 나누면 셋 다 얇아진다
5. **없는 숫자를 만들지 않는다** — 카운터는 셀 수 있게 된 다음부터

## 글은 누가 쓰나

이 스킬은 **배치와 설계**만 합니다. 실제 문장은 이렇게 갑니다.

| | |
|---|---|
| 글쓰기 스킬이 있으면 | 배정표를 넘기고 그쪽에 맡깁니다 |
| 없으면 | 편마다 **뼈대**만 내고 문장은 사용자가 채웁니다 |

> 같은 스킬셋의 **`sns-writing`** 과 짝으로 쓰면 배정표 → 원고까지 이어집니다.
