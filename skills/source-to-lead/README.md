# source-to-lead — 글이 사람을 어디로 데려갈지 정하기

> 🧩 카라 OS · 1차 전환

**글을 쓰는 도구가 아닙니다.** 쓴 글이 **사람을 어디로 보낼지**를 정하는 도구입니다.

---

## 무슨 문제를 푸나

글은 열심히 쓰는데 **신청하는 사람이 없을 때** 씁니다.

대부분의 원인은 하나입니다.

> **글은 있는데, 그 글을 읽은 사람이 「그다음에 뭘 해야 하는지」가 없습니다.**

이 도구는 **글을 쓰기 전에** 그걸 먼저 정합니다.

---

## 어떻게 쓰나

클로드에게 이렇게 말하면 됩니다.

```
이 이야기로 콘텐츠 만들어줘. 신청은 (내 신청 페이지 주소)로 받을 거야
```
```
전단지 만들어야 하는데 QR 어디에 넣지
```
```
어느 채널에서 사람이 왔는지 알고 싶어
```

### 나오는 결과 — 이런 표입니다

```
언제      어디에      무슨 글          링크
9/10     스레드      내 이야기         없음
9/11     인스타      정리해서 보여줌    프로필에
9/13     스레드      결과 알림         신청 페이지 (짧게 줄인 주소)
```

**왜 어떤 글엔 링크가 없냐면** — 매 글마다 링크를 붙이면 사람들이 그 계정을 광고로 봅니다.
특히 **속마음을 쓴 글에 링크가 붙으면, 앞의 진심이 미끼처럼 보입니다.**

그래서 글을 두 종류로 나눕니다.

| 종류 | 링크 | 하는 일 |
|---|---|---|
| **믿게 만드는 글** | 없음 | 이 사람 말을 믿게 만듭니다 |
| **보내는 글** | 있음 | 실제로 신청 페이지로 데려갑니다 |

**믿게 만드는 글 둘에 보내는 글 하나.** 이 비율을 지킵니다.

---

## 여덟 단계로 갑니다

| | 무엇을 정하나 | 나오는 것 |
|---|---|---|
| **0** | 🔴 **어디로 보낼 건가** | 신청 페이지 주소 · 뭘 남기게 할지 · 몇 명이 목표인지 |
| **1** | 이 이야기로 **몇 편**을 쓸 수 있나 | 결론이 몇 개 나오는지로 잽니다 |
| **2** | **어떻게 펼칠 건가** | 네 가지 방법 중 하나 |
| **3** | **어느 채널에** | 편 × 채널 배치표 |
| **4** | **링크를 어디에** | 믿게 만드는 글 / 보내는 글 구분 |
| **5** | **어디서 왔는지 어떻게 아나** | 링크마다 꼬리표를 다르게 붙입니다 |
| **6** | **언제 올릴 건가** | 날짜와 간격 |
| **7** | 올린 뒤 **뭘 세나** | 어느 채널이 잘 굴렀는지 |

### 🔴 0단계가 이 도구의 핵심입니다

**받을 곳을 먼저 정합니다.** 이걸 건너뛰면 그냥 글쓰기 도구가 됩니다.

사람이 와도 갈 데가 없으면, 글을 아무리 잘 써도 소용이 없기 때문입니다.
*"아직 신청 페이지가 없다"* 면 **그것부터 만들자고 말합니다.**

### 주소가 없는 곳으로도 보낼 수 있습니다

목적지에 **주소가 없는 경우**도 있습니다. 슬랙 댓글, 쪽지, 오프라인 모임 같은 것들요.

| | 주소가 있는 곳 | 주소가 없는 곳 |
|---|---|---|
| 예 | 신청 페이지 · 오픈채팅 초대 링크 | **슬랙 댓글** · 쪽지 · 오프라인 모임 |
| 글에 뭘 넣나 | **링크** | **"뭘 하면 되는지" 한 줄** |
| 꼬리표(5단계) | 만듭니다 | **건너뜁니다** |

> 주소가 없을 땐 이렇게 씁니다.
> ❌ *"관심 있으면 연락 주세요"* → 뭘 하라는 건지 모릅니다
> ✅ *"댓글에 「신청」 한 줄만 남겨주세요"*

## 설치

### 맥 · 리눅스

```bash
D=$(mktemp -d) && git clone --depth 1 https://github.com/Kara75-PM/kara-os.git "$D" && bash "$D/install.sh"
```

### 윈도우 (PowerShell)

```powershell
$d = Join-Path $env:TEMP ("kara-os-" + [guid]::NewGuid()); git clone --depth 1 https://github.com/Kara75-PM/kara-os.git $d; powershell -ExecutionPolicy Bypass -File "$d\install.ps1"
```

### 확인

```bash
find ~/.claude/skills/source-to-lead -type f
```

**파일 9개**가 나오면 성공입니다.

### 🔴 설치했는데 안 불릴 때

**클로드 코드를 껐다 켜 보세요.** 처음 설치하는 분은 `.claude/skills` 폴더가 이번에 처음 생겨서,
클로드 코드가 켜질 때 그 폴더를 못 봤기 때문입니다. **고장이 아닙니다.**

## 「내 이야기 폴더」 만들기 — 안 만드셔도 됩니다

없으면 클로드가 물어보면서 진행합니다. **안 깨집니다.**

### 만드는 법 — 클로드에게 시키세요

```
재료 폴더 만들어줘
```

> 🔑 **직접 폴더를 만들지 마세요.** 위치가 조금만 달라도 도구가 못 찾습니다.

그러면 ① 폴더를 만들고 ② 예시가 채워진 파일을 넣고
③ **깃(git) 폴더면 내 이야기가 인터넷에 안 올라가게 막을지 물어봅니다.**

### 만들어지는 파일

| 파일 | 뭘 적나 |
|---|---|
| `destinations.md` | **보낼 곳 목록** — 신청 페이지 주소, 또는 슬랙 같은 「자리」 |
| `utm-terms.md` | **꼬리표에 쓸 말을 고정한 표** — 한 번 정하면 계속 같은 말을 씁니다 |
| `material-stash.md` | 겪은 일을 한 줄씩 |
| `who-i-am.md` | 내가 누구인지 한두 줄 |

> 글쓰기 도구(`sns-writing`)의 「내 이야기 폴더」가 이미 있으면 **그걸 같이 씁니다.**
> 같은 걸 두 군데 두지 않습니다.

## 안에 뭐가 들어 있나

```
source-to-lead/
  SKILL.md          클로드가 읽는 설명서 (사람은 안 읽어도 됩니다)
  README.md         이 파일
  templates/        예시가 채워진 견본 4개
  references/       더 자세한 참고 자료 3개
```

| 참고 자료 | 무엇이 들어 있나 |
|---|---|
| `spread.md` | 이야기 하나를 여러 편으로 펼치는 네 가지 방법 + 실제 예시 |
| `placement.md` | 채널마다 링크를 놓을 수 있는 자리 · **QR 만드는 법과 크기** · 전단 문구 |
| `utm.md` | 꼬리표 만드는 법 · 채널별로 쓸 말 표준표 · **짧은 링크 고르는 기준** |

> **`references/` 가 없어도 도구는 돕니다.** `SKILL.md` 안에 핵심 요약이 들어 있습니다.

## 지키는 것 다섯 가지

1. **받을 곳이 없으면 만들지 않습니다** — 사람이 와도 갈 데가 없습니다
2. **링크는 아껴서 붙입니다** — 매번 붙이면 계정이 광고로 분류됩니다
3. **뿌리는 자리마다 링크를 다르게** — 같은 링크를 세 군데 던지면 셋을 구분 못 합니다
4. **억지로 늘리지 않습니다** — 얇은 이야기를 셋으로 나누면 셋 다 얇아집니다
5. **없는 숫자를 만들지 않습니다** — *"세 자리 남았습니다"* 는 진짜 세 자리일 때만

---

## 글은 누가 쓰나

**이 도구는 배치만 합니다.** 실제 문장은 이렇게 갑니다.

| | |
|---|---|
| 글쓰기 도구(`sns-writing`)가 있으면 | 배치표를 넘기고 그쪽에 맡깁니다 |
| 없으면 | 글마다 **뼈대**만 내고, 문장은 직접 쓰시면 됩니다 |

---

## 이럴 땐 쓰지 마세요

이미 쓴 글의 **문장을 다듬는 일**, 이미 올린 글을 **분석하는 일**.
그건 글쓰기 도구(`sns-writing`)가 합니다.
