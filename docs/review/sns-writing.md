### 1-2. 높은 것부터 — 왜 문제인지

**#1 · #2 비율과 4편** — 가장 눈에 띄는 어긋남입니다.
README 는 「2:1 을 **지킵니다**」, SKILL 은 「2 이상 : 1」, EXAMPLE 의 실제 표는 **2:2** 이고, 같은 EXAMPLE 안에서 「3편이 보내는 글」(4편 빠짐) · 「4편 중 2편에만. 둘에 하나」(2:2 를 2:1 이라 부름)라고 서로 다르게 말합니다.
스킬이 EXAMPLE 을 본보기로 삼으면 **스스로 정한 비율을 어기는 표**를 내게 됩니다.
→ 고칠 방향(제안만): ① 4편을 「믿게 만드는 글」(결과만 알리고 링크 없음)로 바꾸거나, ② 「결과 알리기 글은 보내는 글로 세지 않는다」 같은 예외를 SKILL 에 적거나. 그리고 README 의 「지킵니다」를 SKILL 의 「둘 이상」과 맞춥니다.

**#3 프로필 링크** — 「믿게 만드는 글 = 링크 없음」의 「없음」이 **본문에 링크가 없다**인지 **어디로도 안내하지 않는다**인지 문서마다 다릅니다.
EXAMPLE 은 믿게 만드는 글(2편)에 인스타 프로필용 UTM 링크까지 만들었습니다. 그러면 7단계에서 그 클릭은 「2편 덕」이 아니라 「인스타 프로필 전체」의 클릭입니다(프로필 링크는 글마다 다를 수 없으니까요).
→ 「믿게 만드는 글도 **프로필 안내 한 줄은 된다**, 다만 본문 링크는 없다」처럼 한 문장으로 정해 두면 넷이 맞습니다.

**#4 같은 자리 두 편** — 3편과 4편이 같은 링크를 쓰면 원칙 3(자리마다 다르게)을 EXAMPLE 스스로 어깁니다. `utm_content=post_a/post_b` 를 쓰는 규칙은 SKILL·utm 에 이미 있습니다.

**#5 세는 것은 누구 일인가** — README·SKILL·EXAMPLE 은 7단계에서 **이 스킬이 센다**, utm.md 는 **다른 스킬이 센다**고 합니다. 그 「다른 스킬」은 이 저장소에 없습니다.
utm.md 를 읽는 단계(5단계)에서 스킬이 「세는 건 제 일이 아닙니다」라고 말해 버릴 수 있습니다.

## 3) 한 것 · 못 한 것 · 확인 안 한 것

### ✅ 한 것

- `skills/source-to-lead/` 의 **10개 파일 전부**(README · SKILL · EXAMPLE · references 3 · templates 4)를 끝까지 읽음
- 어긋나는 곳 **21건**을 표로 정리하고 줄 번호를 붙임 (🔴 5 · 🟡 7 · ⚪ 9). 높은 것 5건은 왜 문제인지 따로 풀어 씀
- 부르는 말 **10개**, 부르면 안 되는 말 **5개**와 각각의 맞는 반응·근거를 적음. 표에 못 넣은 **경계 사례 4개**를 따로 적음
- 부르는 말이 겹치는지 보려고 `skills/sns-writing/SKILL.md` · `skills/material-harvest/SKILL.md` 의 설명문(맨 위 몇 줄), 루트 `README.md`, `install.sh` 의 안내 문구를 확인함
- `find skills/source-to-lead -name '*.md'` 가 **10개**로 README 의 「문서 10개」 `README:122` 와 맞는 것을 확인함
- `skills/` 아래 파일은 **하나도 고치지 않음**. 바뀐 파일은 `docs/review/sns-writing.md` 하나
- 새 브랜치 커밋 → 새 PR 을 엶. **합치지 않음**

### ❌ 못 한 것

- **스킬을 실제로 불러 보지 못함.** 2) 의 「맞는 반응」은 문서에서 끌어낸 기대값이지, 클로드 코드에서 15개 말을 쳐 보고 확인한 결과가 아님
- 어긋난 곳을 **고치지 않음** — 요청이 「skills 폴더 안 파일은 고치지 마」였으므로 고칠 방향은 제안으로만 적음
- **파일 이름** — 요청대로 `docs/review/sns-writing.md` 로 만들었지만, 내용은 source-to-lead 검토입니다. 이름이 의도한 것인지 확인하지 못했습니다. `source-to-lead.md` 가 맞다면 이름만 바꾸면 됩니다

### ❓ 확인 안 한 것

- **EXAMPLE 맨 끝 「실제로 스킬을 돌려서 나온 것을 그대로 옮긴 것」** `EXAMPLE:276` — 정말 그런지 확인 안 함. 1-1 #1·#2·#4 처럼 문서 안에서 서로 어긋나는 걸 보면 손으로 고친 부분이 섞였을 수 있음
- **플랫폼 사실관계** — 인스타 캡션 링크가 안 눌리는지, 스토리 링크 스티커 조건, 스레드 본문 링크 동작, 단축 링크 서비스의 무료 조건. 문서도 「바뀔 수 있다」고 적어 둠 `placement:184-191`, `SKILL:339`. 이번에 찾아보지 않음
- **구글폼이 UTM 값을 응답에 남기는지** — EXAMPLE 의 목적지가 구글폼인데, 7단계 「채널별 남겼다」를 채우려면 폼 쪽에서 어느 링크로 왔는지 알아야 함. 구글폼은 주소 뒤 UTM 값을 응답에 저장하지 않는 것으로 알고 있으나 **이번에 확인하지 않았음.** 맞다면 EXAMPLE 의 7단계 표는 「눌렀다」만 채널별로 채워지고 「남겼다」는 채울 수 없음
- **`.gitignore` · 재료 폴더 동작** — `git check-ignore` 확인, 「없는 견본만 채운다」, 둘 이상 찾으면 묻기 등을 실제로 돌려 보지 않음

- `install.sh` · `install.ps1` 은 안내 문구 몇 줄만 봤고 **돌려 보지 않음**
